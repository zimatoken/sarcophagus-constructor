# Технический аудит и усиление — v2.1.1

Дата проверки: 18.11.2026  
Основание: содержимое исходного `sarcophagus-constructor.zip` (38 записей, около 5.7 MB распакованных данных).

## 1. Итоговый вердикт

**Исходный проект — полезный рабочий прототип с хорошим содержательным ядром, но с разрывами между версиями и несколькими дефектами целостности данных.** Он не требовал полного переписывания. Поэтому классическая v1.4 сохранена, а улучшения внесены в отдельную основную ветку `web-v2` с точкой входа в корне.

## 3. Архитектурное решение

- `index.html` — безопасная точка входа с явным выбором основной и классической версии.
- `docs-app/` — рекомендуемая ветка v2.1.
- `web/` — исходная v1.4, сохранена как legacy/reference.
- `src/` — промпты, шаблоны, примеры и библиотека знаний; не переписывались без необходимости.
- `scripts/` — локальный сервер и статический контроль целостности.
- `tests/` — автоматические тесты на встроенном Node.js test runner.

Никаких backend, облачной синхронизации, внешних API или сторонних npm-зависимостей не добавлено.

## 4. Дополнительные усиления

1. Экспорт JSON — переносимость и резервная копия.
2. Импорт JSON — проверка формата, ограничение файла 2 MB, подтверждение перезаписи.
3. Локальный статус сохранения — пользователь видит результат записи в localStorage.
4. Сохранение этапа — после перезагрузки можно продолжить с восстановленного шага.
5. Копирование результата — отдельные действия для SHORT и FULL.
6. Мобильные стили и focus-visible — удобство на узких экранах и клавиатурная навигация.
7. Тесты и `npm run check` — быстрая проверка синтаксиса, структуры библиотеки и ассетов.

## 6. Архитектурный разрыв, который нельзя скрывать

В проекте существуют два параллельных способа построения саркофага:
- системный промпт `src/prompts/` ведёт диалог по веткам A/B/C/D;
- браузерный конструктор строит документ по библиотеке M01–M27.

Шаблоны `type-a-active.md` и `type-b-ecosystem.md` описывают отдельные блоки, но браузерный генератор не подключает их напрямую. Это не блокирует работу MVP, однако может приводить к разной полноте документа в зависимости от выбранного способа. Добавлен промпт v1.2 с правилами доказательности и точного разделения фактов/гипотез; объединение двух сценариев оставлено отдельной следующей фазой, чтобы не делать рискованный рефакторинг без тестовой спецификации.

## 9. Исправление сборки v2.1.1 после Windows-проверки

В первой переданной сборке тесты и `scripts/check.mjs` вычисляли корень проекта через `new URL('../', import.meta.url).pathname`. На Windows поле `pathname` сохраняет ведущий `/` перед буквой диска; последующий `path.join` формировал некорректный путь вида `E:\\E:\\...`. Это приводило к ENOENT для всех файловых проверок и к ложному падению проверки иконок.

Исправление: оба скрипта используют `fileURLToPath(new URL('../', import.meta.url))`, что корректно преобразует file URL в системный путь Windows. Проверки не отключались и ожидания не ослаблялись. После исправления подтверждено: `npm test` — 5/5 PASS; `npm run check` — PASS, 4 JS-файла разобраны, 27 уникальных модулей, общий путь иконок доступен.


## Дополнение: v2.2.0 — UX/regression fix (2026-11-18)

- Добавлены контекстные кнопки помощи для типа проекта, обязательных полей, опциональных блоков и финализации.
- Модульные подсказки и подсказки полей открываются через единый modal; текст вставляется через `textContent`.
- Добавлены стили режимов, кнопок помощи и radio controls.
- Логотип добавлен в заголовок v2.2, стартовую страницу и favicon.
- Добавлен MIME для `.webp` в локальный сервер.
- v1.4 оставлена без изменений.
