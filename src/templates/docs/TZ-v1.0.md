1. ЦЕЛЬ И НАЗНАЧЕНИЕ
Создать детерминированный, интеллектуальный конструктор для генерации стандартизированных документов («Саркофагов»), которые выполняют три функции:
Мгновенный онбординг: Любой AI или человек подхватывает контекст проекта за 30 секунд без потери качества.
Архитектурная дисциплина: Фиксация состояния проекта на контрольных точках (аудит + план), исключая хаос в разработке.
Масштабирование дохода: Превращение разовых разработок в переиспользуемые активы (капсулы памяти) для генерации пассивного дохода.
2. АРХИТЕКТУРА КОНСТРУКТОРА (Логика работы)
Конструктор работает в режиме диалогового интервью с детерминированным ветвлением.
Вход: Пользователь инициирует команду /саркофаг или «Начни конструктор».
Процесс: Пошаговый опрос (Этапы 0–4). Конструктор задаёт только релевантные вопросы на основе выбранного типа проекта.
Валидация: Если обязательный блок (например, 1.7 Архитектура) пропущен или размыт, конструктор задаёт уточняющий вопрос.
Выход: Генерация двух форматов:
Short Capsule (1 экран: суть, статус, следующий шаг для быстрого подхвата AI).
Full Sarcophagus (полный Markdown-документ со всеми деталями, готовый к сохранению в .md).
3. ЯДРО САРКОФАГА (Этап 1: Обязательные блоки)
Присутствует в 100% случаев, независимо от типа проекта.
ID
Блок
Описание и требования к заполнению
1.1
Идентификация
Название проекта + Версия саркофага (например, v4.1) + Дата контрольной точки.
1.2
Статус
Эмодзи-индикатор: ✅ Стабильный, 🟡 В разработке, ⚠️ Риски, 🏁 Закрыт.
1.3
Философия
4–8 непреложных принципов (например: «Руль у пользователя», «Честность важнее фичи»).
1.4
Назначение
1–2 предложения: какую главную проблему решает проект и для кого.
1.5
Архитектура
Высокоуровневый слепок: ключевые слои, дерево папок (укрупнённо), основной стек технологий.
4. МОДУЛИ ВЕТВЛЕНИЯ (Этап 2: Специфика типа)
Конструктор активирует только один из четырёх модулей на основе выбора на Этапе 0.
🔹 Тип А: Активный продуктовый (Золотой Инвестор, Financial System, SOS)
Фокус: Скорость доставки ценности, стабильность, монетизация.
A2.1 Статус фич/модулей (Таблица: Модуль | Статус ✅/🟡/❌).
A2.2 Ключевые правила и запреты (Что категорически нельзя ломать).
A2.3 Дорожная карта (Приоритетные фазы на ближайший спринт).
A2.4 Правила деплоя (GitHub, GitHub Pages, окружения).
A2.5 История багов и фиксов (Топ-3 решённых критических проблемы).
A2.6 Метрики и ценность (Как именно это генерирует доход или пользу).
🔹 Тип B: Экосистема / Семейство приложений («Я в натуре»)
Фокус: Целостность, стандартизация, переиспользование.
B2.1 Реестр приложений (Название | Версия | Статус).
B2.2 Единая оболочка (Общие компоненты: store, theme, registry, роутинг).
B2.3 Стандарты кода и данных (Единые правила именования, форматы API).
B2.4 Дорожная карта волн (План синхронного обновления экосистемы).
🔹 Тип C: Закрытый проект / Урок (Дикий Инвестор)
Фокус: Извлечение активов, честный анализ, недопущение повторения ошибок.
C2.1 Итоговый вердикт (Успех / Провал / Смешанный результат).
C2.2 Что сработало (Элементы, доказавшие эффективность).
C2.3 Причины неудач (Честный разбор без самообмана).
C2.4 Ключевые выводы (Методологические уроки для будущих проектов).
C2.5 Активы для переиспользования (Код, идеи, скрипты, которые забираем с собой).
C2.6 Финальная философская запись (Краткий итог для истории).
🔹 Тип D: Сложное ядро + Compatibility Layer (TAX SHIELD)
Фокус: Безопасность, доказательность, строгая иерархия.
D2.1 Разделение слоёв (Чёткая граница: Приложение / Ядро / Compatibility).
D2.2 Runtime-аудит (Что реально загружено в память, а что мёртвый код).
D2.3 Статусы доказательности (ПОДТВЕРЖДЕНО КОДОМ / ПОДТВЕРЖДЕНО ТЕСТАМИ).
D2.4 Жёсткие запреты (Красные линии архитектуры).
D2.5 Приоритеты с зависимостями («Не начинать X, пока не закрыт Y»).
5. ОПЦИОНАЛЬНЫЕ МОДУЛИ (Этап 3)
Предлагаются конструктором, пользователь выбирает Да/Нет.
3.1 Текущий фактический статус (детализация того, что реально работает прямо сейчас).
3.2 Подробные чек-листы (для аудита или релиза).
3.3 Известные ограничения и риски (Technical Debt, внешние зависимости).
3.4 История изменений этой версии саркофага (Changelog документа).
3.5 Ссылки и деплой (Репозитории, live-демо, документация API).
6. ФИНАЛИЗАЦИЯ И СТИЛЬ (Этап 4)
4.1 Памятка для AI: Стандартная фраза: «Скинь этот саркофаг новому AI + скажи, на каком этапе остановился. Руль у тебя.»
4.2 Стиль генерации: Деловой, но «живой». Использование эмодзи как визуальных якорей. Абсолютная честность (никакого "watermelon status" 🟢 снаружи, 🍉 внутри).
4.3 Формат выдачи: Один Markdown-блок, разделённый на --- SHORT CAPSULE --- и --- FULL SARCOPHAGUS ---.
