🧭 1. Философия / Принципы
Сначала достоверность. Затем архитектура. Затем реализация. Затем проверка.
Паспорт описывает фактическое состояние проекта, а не желаемое будущее.
Наличие типа, интерфейса или теста ≠ реализация пользовательской функции.
Не переводить правила из DRAFT в VERIFIED по собственному предположению.
Не подключать Phase 1 к runtime без отдельного решения.
Руль у владельца — любые изменения только после согласования.
Сохраняем рабочее. Проверяем факты. Меняем только по согласованию.
TAX SHIELD должен понимать: кому, на каком основании, за какой период и при каких условиях применимо налоговое правило.
🎯 2. Назначение
Демонстрационное браузерное приложение с отдельным TypeScript-ядом для анализа хозяйственных операций, налоговых правил, подтверждающих документов и сигналов, требующих проверки. Цель — не просто калькулятор налогов, а система, которая помогает понять, что произошло, какие документы нужны, какие риски есть и когда требуется специалист.
🏗️ 3. Архитектура
Слой «Приложение» (src/): UI (шаблонные строки + DOM), state.ts (composition root), demoOperations.ts, Legacy-адаптеры (LocalStorage), демонстрационный профиль (ООО «СибПак»).
Слой «Налоговое ядро» (tax-shield-core/): domain/ (Legacy types + Universal v1/v2), engine, accountant, auditDetector, rules/, compatibility/ (Phase 1), adapters/, memory/, utils/.
Граница ответственности: Приложение знает только Legacy-контракт. Ядро не знает про UI и localStorage. Phase 1 живёт внутри ядра, но наружу через index.ts не торчит.
Публичный API ядра: Только Legacy-контракты через tax-shield-core/src/index.ts. Phase 1 модули намеренно не экспортируются.
Стек: TypeScript, Vite, localStorage. (Backend, внешние API и БД отсутствуют).
