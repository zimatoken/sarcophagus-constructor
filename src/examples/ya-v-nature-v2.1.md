🧭 1. Философия / Принципы
Принцип Оболочки (The Shell): любое новое приложение строится на едином каркасе. Меняется только папка data и специфические модули.
Offline-First: всё работает без интернета (PWA, Service Worker, LocalStorage / IndexedDB).
Геймификация: XP, уровни, стрики, достижения, племена. Обучение через игру.
Единый Хаб: life-hub связывает все приложения, суммирует XP и хранит глобальный профиль.
Глубина, а не поверхность: если делаем «Географа», там будут опасные животные, типы дорог и 3D-ландшафт, а не просто список стран.
Данные отделены от логики.
Никаких тяжёлых фреймворков: только Vanilla JS для максимальной скорости, оффлайн-работы и простоты поддержки.
Единая тема управляется одним ключом во всей экосистеме.
🎯 2. Назначение
Экосистема оффлайн-первых PWA-приложений «Я в натуре [X]», которые превращают обычные справочники и навыки в глубокие, геймифицированные инструменты. Цель — дать человеку практическую глубину в разных сферах жизни через единый привычный интерфейс и общую прогрессию.
🏗️ 3. Архитектура
Единая оболочка: core/ (registry.js, store.js, theme.js, engine.js), единые стили (css/styles.css), Service Worker + manifest.json, глобальный механизм XP/прогресса, связь с Хабом.
Структура каждого приложения:
text
  ya-v-nature-X/
  ├── index.html
  ├── manifest.json
  ├── sw.js
  ├── core/               # общее (ссылки или копии)
  ├── css/
  ├── data/               # самое важное — база данных приложения (JSON/объекты)
  └── modules/            # encyclopedia, sos, planner, journal и т.д.
Стек: Vanilla JS, PWA (Service Worker), LocalStorage / IndexedDB. Без React/Vue/Angular.

Связь с Хабом (life-hub) для суммирования XP и глобального профиля
B2.3 Стандарты кода и данных
Данные строго отделены от логики — вся база лежит в data/items.js (или аналогичных файлах) и загружается через registry.js.
Никаких фреймворков (React / Vue / Angular) — только чистый Vanilla JS.
При генерации данных через Python всегда использовать json.dumps(..., ensure_ascii=False).
Единая тема управляется одним ключом во всей экосистеме.
Новые приложения создаются скриптом create_ya_v_nature_X.py по единому шаблону.
Модули (encyclopedia, sos, planner, journal) подключаются единообразно.

5.1 Подробные чек-листы
Чек-лист создания нового приложения через create_ya_v_nature_X.py:
Скрипт выполнен успешно, создана базовая структура папок.
Файл data/items.js сгенерирован с флагом ensure_ascii=False.
Ключ темы в localStorage унифицирован (ecosystem_theme_universal_v2).
Модули подключены через единый интерфейс registry.js.
Чек-лист перед пушем приложения в GitHub:
Приложение протестировано в режиме Offline (Service Worker корректно кэширует).
Версия в manifest.json и заголовке актуализирована.
Код проверен на отсутствие хардкода и соответствие стандартам Vanilla JS.
Репозиторий инициализирован, .gitignore настроен (исключает ненужные локальные файлы).
5.2 Известные ограничения и риски
⚠️ Рассинхрон версий: 5 приложений существуют только локально, риск потери данных или расхождения с эталонами.
⚠️ Единая точка отказа темы: Зависимость всей экосистемы от одного ключа ecosystem_theme_universal_v2 в localStorage.
⚠️ Отсутствие CI/CD: Нет автоматической проверки единообразия кода при пуше.
⚠️ Риск «расползания» стандартов: Если новые приложения будут создаваться вручную, а не через скрипт create_ya_v_nature_X.py.
