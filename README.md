# 🛡️ Конструктор Саркофагов — v2.2.1 — v2.3.0 Guided Edition

**Статус:** усиленная offline-first сборка  
**Принцип:** «Руль у пользователя»  
**Основная точка входа:** `index.html`

## Что это

Конструктор помогает структурировать знания о проекте и сформировать два переносимых документа:
- **SHORT CAPSULE** — краткий контекст для быстрого старта нового AI-сеанса.
- **FULL SARCOPHAGUS** — подробный документ с архитектурой, модулями, решениями, рисками и правилами продолжения.

Это не подключённый AI-агент: диагностический режим использует локальные эвристики и ключевые слова. Он предлагает стартовую гипотезу, а не анализирует проект автоматически и не обращается к внешней модели.

## Быстрый запуск

**Самый простой вариант:** открой `index.html` в современном браузере.

**Через локальный сервер (рекомендуется для Clipboard API):**
```bash
npm start
```
Открой `http://127.0.0.1:4173`.

Node.js 18+; внешние npm-зависимости не нужны.

## Данные и приватность

- Черновик хранится в `localStorage` браузера на текущем устройстве и в текущем профиле браузера.
- Сервер не нужен; при запуске через локальный сервер он только раздаёт статические файлы.
- Автоматической синхронизации между устройствами нет.
- JSON-экспорт — рекомендуемый способ резервного копирования и переноса проекта.
- Очистка данных сайта/браузера может удалить локальный черновик. Экспортируй JSON перед очисткой.

## Проверка

```bash
npm test
npm run check
```

Тесты проверяют синтаксис JS, состав и уникальность библиотеки модулей, диагностические ID, комплектность ассетов и ключевые элементы импорта/экспорта. Это статическая проверка, а не полноценный браузерный E2E-тест.

## Структура

- `docs-app/` — рекомендуемый интерфейс и логика v2.2
- `web/` — классическая версия v1.4
- `src/prompts/` — системные промпты
- `src/templates/` — шаблоны и библиотека модулей
- `src/examples/` — примеры саркофагов
- `docs/` — аудит, архитектура, контроль качества
- `scripts/` — локальный статический сервер и проверки
- `tests/` — тесты Node.js built-in test runner

## Важное различие двух режимов

- Браузерная версия создаёт документ по полям и библиотеке из 27 модулей.
- Системный промпт — отдельный сценарий интервью с AI и более подробными ветками A/B/C/D.
- Эти два сценария пока не имеют общего runtime-контракта: не предполагай, что выбор модуля в браузере автоматически выполняет все вопросы системного промпта.

## Ограничения

1. Диагност не является LLM и может ошибаться в классификации.
2. Содержимое пользовательских полей не проверяется на фактическую истинность.
3. Ссылки и статусы проекта пользователь должен подтверждать самостоятельно.
4. Импорт JSON заменяет текущий черновик только после подтверждения.
5. Не вводи секреты, пароли, приватные ключи и персональные данные в экспортируемые документы.

**Решение и ответственность всегда остаются у пользователя.**

## Production Hardening v2.4.0

The current hardened release validates imported JSON before replacing the draft, normalizes imported values against the known schema and module IDs, improves help-dialog keyboard accessibility, and labels Diagnostic mode honestly as a local keyword heuristic. See `docs/RELEASE_NOTES_v2.4.0.md` and `docs/PRODUCTION_HARDENING_REPORT_v2.4.0.md`.

**Data safety note:** drafts are stored in this browser profile using `localStorage`; they are not synced to another device and can be lost if browser site data is cleared. Export a JSON backup before major edits, browser cleanup, or moving to another computer.
